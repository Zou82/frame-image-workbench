# FRAME Android Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans task by task.

**Goal:** Build, run in emulators, and deliver a signed standalone FRAME APK.

**Architecture:** Reuse the React interface through an asynchronous trusted-origin
bridge. Java owns API connections, persistence, media and background generation.

**Tech Stack:** React/Vite, Android Java, platform WebView/HttpURLConnection,
Gradle 8.2/AGP 8.2.2, JDK 17, SDK 34.

**Spec:** `docs/superpowers/specs/2026-11-15-android-design.md`

## Global Constraints

- minSdk 26, compileSdk 34, targetSdk 34.
- No native ABI libraries and no desktop server dependency.
- 100 concurrent tasks, 500 drafts, 20 connections, 16 references, 20 MB per reference.
- No embedded private credentials, generated desktop images, or paid test requests.
- No automatic generation retries on restart.
- All adb device operations use an explicit emulator serial.
- Preserve existing desktop functionality and user data.

## Task 1: Native Backend

**Files:** `android/app/src/main/java/com/frame/workbench/{Backend,Store,Provider,TaskRules}.java`,
`android/app/src/androidTest/java/com/frame/workbench/BackendTest.java`.

**Interfaces:**

```java
Backend.get(Context context)
JSONObject Backend.call(String method, String route, JSONObject body) throws Exception
File Backend.mediaFile(String id) throws Exception
void Backend.setListener(Runnable listener)
int Backend.activeCount()
```

UI-specific `/export` and `/clipboard` are handled by the shell, not Backend.
Backend `call` returns JSON responses matching the desktop API. It is invoked on
a bridge worker thread. Settings encryption and history serialization are private.

- [ ] Write instrumentation behavior tests for public-key omission, persisted keys,
  true model syncing, rejected invalid task, multipart/payload, cancellation and restart.
- [ ] Run tests with missing implementation to establish the failure.
- [ ] Implement storage/validation/provider/queue, bounded responses and atomic files.
- [ ] Run emulator tests against a strict localhost fixture; report evidence.

## Task 3: Emulator Acceptance and Delivery

**Files:** `tools/android-*`, `docs/android-testing.md`, `releases/FRAME-1.0.0.apk`.

- [ ] Create dedicated emulator and fixture provider.
- [ ] Install and test real UI with tree-derived taps and CDP assertions.
- [ ] Verify settings/models, JSON import100, bulk and individual settings,
  generation100/concurrency, uploads/multipart, cancellation/errors, gallery/reuse,
  file save/import, background, recreation, force-stop/restart.
- [ ] Test portrait/landscape/tablet/font scaling and an older Android version.
- [ ] Review new source for API, lifecycle, security and compatibility regressions.
- [ ] Fix confirmed defects, rerun affected tests, produce signed release APK.
- [ ] Record APK SHA256, signature, tested platforms and limitations; deliver link.

## Execution Notes

No Git repository exists. Keep the source, plan and evidence in place. Use an
independent backend implementer while the primary builds the disjoint UI shell.
Review the integrated result before packaging. Never remove the user's workspace.
